# bAD

bAD собирает сведения о компьютерах Windows и показывает их в одной панели. На каждом ПК стоит агент. Сервер хранит снимки у вас, не в чужом облаке.

Сейчас сервер версии 3.1.8, агент версии 3.1.6. Номера лежат в файлах `VERSION` и `agent/VERSION`.

## Что умеет

Агент снимает оборудование, систему, пользователей и список программ и время от времени отправляет это на сервер. В панели у каждой машины своя карточка: железо, сеть, программы, события, минидампы.

Новый ПК не получает код установки. Он оставляет заявку. На странице **Устройства** виден счётчик заявок и кнопка **«Заявки»**. Список и кнопка **«Разрешить»** — на отдельной странице. Пустой номер устройства заводит новую карточку. Если номер уже есть у живой не отозванной карточки, «Разрешить» меняет ключ этой строки. Отозванную карточку кнопка не возвращает. Исключение одно: номер `6f0bc3d6-87c4-4608-9c01-e6e7c7d2e6c5` ключ не получает и старую карточку не меняет.

Снимок можно подписывать. Пока подпись включена, сервер не принимает неподписанный inventory.

Сервер умеет обновлять сам себя и раздавать новый MSI агента. Агент забирает установщик с вашего сервера.

## Как поставить сервер

Нужен Debian 12. В каталоге `deploy/debian` этого репозитория:

```bash
BAD_DOMAIN=panel.example.com sudo -E bash install.sh
```

Скрипт ставит PostgreSQL, nginx и службу. Сразу после установки панель открывается по HTTP. Сертификат загружается в **Параметры → Сертификат**, дальше панель живёт на HTTPS.

Первый вход: `admin` / `admin`. Пароль сразу нужно сменить.

Пошаговая установка, сертификат и первая заявка расписаны в [docs/ste-100.md](docs/ste-100.md). Этот README ту инструкцию не заменяет.

Для разработки сервер можно поднять из каталога `server/`: Python 3.11, переменная `BAD_DATABASE_URL` на PostgreSQL, затем `uvicorn bad_server.app:app --host 127.0.0.1 --port 8000`.

## Как поставить агент

На ПК Windows агент ставится MSI. Адрес сервера передаётся так: `SERVERURL=https://panel.example.com`. После установки машина появляется в заявках. **«Разрешить»** выдаёт ей ключ, служба `badagent` забирает его сама.

Сборка из исходников: каталог `agent/`, команда `dotnet build BadAgent.sln -c Release`. Описание MSI — в [installer/msi/README.md](installer/msi/README.md).

Агент ходит на сервер только по `https://`.

## Команды

Обычные команды выполняет служба `badagent`, и для пользователя, и для администратора. Сама программа `bad` ключ не читает и на сервер не ходит. Если служба не запущена, в колонке будет **ошибка**.

`bad service` и `bad uninstall` по-прежнему только для администратора: они управляют службой и снятием, а не опросом сервера.

Команды `bad ping` нет. Связь смотрите в `bad info`: пять строк о машине и в конце строка **Связь**.

| Команда | Зачем |
| --- | --- |
| `bad` | Локальный отчёт, без сервера |
| `bad info` | Версия, сервер, имя, device_id, модель и связь |
| `bad -r` | HTML-отчёт. Снимок собирается на ПК, на сервер его относит служба |
| `bad -c` | Настройка агента по шагам |
| `bad config` | Показать настройки. Секреты не печатаются |
| `bad config set` | Один параметр |
| `bad push` | Очередь, снимок, heartbeat |
| `bad update` | Проверить версию и поставить MSI, если он есть |
| `bad doctor` | Связь, потом обновление, потом сброс лишних настроек |
| `bad service` | Статус, запуск, остановка и перезапуск службы |
| `bad uninstall` | Снять агент |

`bad doctor` идёт в таком порядке. Если адреса сервера нет, будет одна строка и больше ничего. Если сервер не ответил, связь **нет**. Если сервер ответил отказом ключа, связь **есть**, ключ **отклонён**, заявка ждёт **«Разрешить»**: обновление и сброс не делаются. Если ключ принят, сначала строка обновления, и только потом сброс настроек и стирание ключа подписи. Адрес, номер устройства и ключ доступа при сбросе не трогаются.

Справка: `bad -h`. В ней три блока: отчёт, сервер, служба.
