# Релизные заметки — сервер 1.10.0

Релиз **надёжности и производительности** (без смены контракта API для интеграций). Рекомендуемый агент: **1.3.0** ([release-notes-agent-1.3.0.md](release-notes-agent-1.3.0.md)).

## Регистрация агентов и данные устройств

- Параллельные запросы при **регистрации** и обновлении **служебных полей** устройства обрабатываются аккуратнее: меньше гонок и «странных» состояний в парке.
- Отозванное устройство **не восстанавливается** повторной регистрацией только по enrollment-токену — проверка усилена.

## Вход в панель

- Роль и статус **локального** пользователя при каждом запросе сверяются с **БД** (смена роли подхватывается без обязательного повторного входа).
- Для **LDAP** роль берётся из текущих настроек каталога на сервере.

## Связь с агентом (heartbeat)

- Ответ **легче**, если у агента уже актуальная версия политики: полный набор настроек приходит только при **смене версии** или по запросу **«Обновить политику и версию»** с панели.

## События и поиск

- В **списках** событий (панель и API) по умолчанию **нет тяжёлых деталей** — они остаются в БД и на **странице события**.
- **Глобальный поиск** на Обзоре и поиск по устройствам на больших парках работают **быстрее** за счёт индексов в БД (при старте сервер пытается их создать; без расширения `pg_trgm` поиск остаётся как раньше).

## Почта (SMTP, сводка digest)

- События помечаются «отправленными в digest» **только после успешной** отправки письма. Если письмо не ушло или все строки отфильтрованы настройками уведомлений, очередь **не сбрасывается** ошибочно.

## Установка и разработка

- Каталог зеркала **MSI агента** на сервере: в проде по умолчанию **`/var/lib/bad/agent-updates`** (переменная `BAD_AGENT_UPDATES_DIR`). В lab, если нет прав на этот путь, используется запасной каталог в `data_dir`.
- Номера версий сервера в пакете, health и панели **синхронизированы** (`1.10.0`).
