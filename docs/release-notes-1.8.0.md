# Релизные заметки — сервер 1.8.0, агент 1.2.1

## Панель: парк и первые шаги

- **Обзор:** мастер «Первый запуск» (шаги до рабочего HTTPS и первого ПК); прогресс для UI — `GET /setup/progress.json`.
- **Устройства:** пустой парк — подсказка перейти к установке агента; **пагинация** длинных списков; **сброс фильтров**; **массовые действия** (архив, добавить тег) через `POST /devices/bulk`.
- Ссылки на узлы с **иконкой типа корпуса** (`devices.meta.chassis_type`: ноутбук, настольный ПК, сервер, ВМ, другое).
- **События:** группы «Сегодня» / «Ранее»; относительное время в ленте (`local-time.js`).
- **Безопасность:** после загрузки cert сервер отклоняет регистрацию агента по HTTP (`403`, текст `ENROLL_CLEARTEXT_MSG`); lab — `BAD_ALLOW_ENROLL_OVER_HTTP=1`.

## API (без ломающих изменений)

- `GET /v1/events` — лёгкий список: поле `importance`, **без** `detail` в JSON (детали остаются в БД для панели и почты).

## Панель: принудительное обновление политики и проверка MSI

- На карточке устройства (admin): кнопка **«Обновить политику и версию»** — одноразовый запрос к агенту при следующем heartbeat (pull-only: флаги в `devices.meta`, без push с сервера).
- Сервер в ответе heartbeat отдаёт полный remote `config` (даже если `config_version` не менялся) и `actions`: `inventory`, `update_check` — по флагам запроса.
- Admin API: `POST /v1/devices/{device_id}/request-refresh`.

## Агент 1.2.x → 1.2.1

- Обработка `actions` в ответе heartbeat (принудительный inventory и проверка обновления MSI).
- CLI **`bad push`** / **`bad push --update`** — локально то же на машине (очередь → inventory → heartbeat; опционально update).
- Кэш тяжёлых секций сбора при неизменной конфигурации машины; корпус (`chassis_type`) собирается всегда.
- HTML **`bad -r`:** относительное время свежести, как в панели.
