# STE-100 — поток для ветки beta

Короткий сценарий для ветки **beta**: клиенты **без общего токена** регистрации, **подпись** снимка инвентаря, **флаги** на сервере, **HTML-отчёт** через API сервера и **разбор минидампа** по кнопке в панели.

Детали API: [api-v1.md](api-v1.md).

---

## Общие шаги

1. Задайте у агента в конфигурации параметр `server_url` с адресом **https://** вашего сервера.

2. Отключите режим **общего токена регистрации** для всех ПК: в панели в **Параметрах** снимите флаг **«Общий токен регистрации»** (настройка `allow_shared_enrollment`).

3. Дальше выполните **либо** шаги 4–7 (подключение по **заявке** без кода), **либо** шаги 8–11 (подключение по **одноразовому коду**).

## Подключение по заявке (без общего токена)

4. На новом ПК выполните перезапуск службы агента командой `bad service restart`.

5. Откройте в панели раздел **Устройства** и дождитесь появления строки **заявки** на регистрацию с этого ПК.

6. В строке заявки нажмите **«Разрешить»**.

7. На этом ПК выполните `bad push` и дождитесь успешной отправки инвентаря.

## Подключение по одноразовому коду

8. В панели в разделе **Устройства** нажмите кнопку выдачи **одноразового кода регистрации** («Код регистрации»).

9. Скопируйте показанный код в буфер обмена и закройте диалог.

10. На целевом ПК запишите этот код в конфигурации агента в поле `enrollment_code` и сохраните файл.

11. На целевом ПК выполните `bad service restart`, затем при необходимости один раз `bad push`.

## Подпись инвентаря

12. В **Параметрах** панели включите **«Требовать подпись инвентаря»** (`require_inventory_signature`).

13. На каждом ПК выполните `bad push` до тех пор, пока снимок принимается без ошибки подписи (агент получает ключ подписи у сервера после регистрации).

Альтернатива для шага 12: на сервере задайте `BAD_REQUIRE_INVENTORY_SIGNATURE=1` и перезапустите службу сервера **один раз** после изменения.

## Флаги окружения (сервер)

14. Запомните сочетание: **`BAD_ALLOW_SHARED_ENROLLMENT=0`** — без общего токена для всех; **`BAD_REQUIRE_INVENTORY_SIGNATURE=1`** — отказ в приёме снимка без подписи.

15. Не вставляйте в документы и тикеты значения выданных токенов и ключей.

## HTML-отчёт с сервера

16. Убедитесь, что в конфигурации агента на ПК заданы `server_url` (**https://**) и `api_key` (после успешной регистрации).

17. Выполните на этом ПК команду `bad -r` без дополнительных аргументов.

18. Откройте сохранённый файл `bad_report_….html` в браузере и сверьте оформление с карточкой устройства в панели.

## Минидамп BSOD по кнопке

19. Откройте в панели карточку нужного устройства и перейдите к блоку **«Минидампы BSOD»**.

20. В списке файлов выберите минидамп с расширением `.dmp`, **кроме** `Memory.dmp`.

21. Нажмите кнопку **«Разобрать»** под этим файлом.

22. Дождитесь следующего цикла работы агента на ПК (служба запущена), чтобы агент получил от сервера действие на выгрузку файла.

23. Обновите страницу карточки устройства в браузере и проверьте поле **«Причина»** для выбранного файла.
