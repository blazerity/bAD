# STE-100

Инструкция для панели bAD 3.1.3. Каждый номер — одно действие. Имена кнопок совпадают с панелью.

Новый ПК подключается заявкой. Панель код установки не выдаёт.

## Сервер

1. На Debian 12 откройте каталог `deploy/debian` этого репозитория.
2. Выполните `BAD_DOMAIN=<домен> sudo -E bash install.sh`.
3. Откройте в браузере `http://<домен>/login`.
4. Введите логин `admin` и пароль `admin`.
5. Откройте **Параметры → Смена пароля**.
6. В поле **«Текущий пароль»** введите `admin`.
7. В поле **«Новый пароль»** введите новый пароль длиной не меньше 8 символов.
8. В поле **«Подтверждение»** введите тот же новый пароль.
9. Нажмите **«Сохранить пароль»**.
10. Откройте **Параметры → Сертификат**.
11. В поле **«Сертификат (PEM)»** выберите файл сертификата.
12. В поле **«Закрытый ключ (PEM)»** выберите файл закрытого ключа.
13. Нажмите **«Установить сертификат»**.
14. Откройте `https://<домен>/login`.

## Подпись снимка

15. Откройте **Параметры → Обновления агента**.
16. Включите флажок **«Требовать подпись снимка»**.
17. Нажмите **«Сохранить»**.

## Новый ПК

18. На ПК Windows выполните от имени администратора `msiexec /i bad-agent-3.1.3.msi SERVERURL=https://<домен>`.
19. Откройте в панели раздел **Устройства**.
20. В полосе **«Заявки на подключение»** нажмите **«Заявки»**.
21. Дождитесь строки этого ПК со статусом **«Ожидает разрешения»**.
22. В этой строке нажмите **«Разрешить»**.
23. На этом ПК выполните `bad push`.

Команду из шага 23 выполняет служба `badagent`: она забирает ключ подписи и отправляет подписанный снимок. Повторная установка на тот же ПК снова показывает заявку на ту же карточку.

Список программ собирается сам. Чтобы его выключить, на карточке откройте **«Параметры агента»**, в поле **«Собирать ПО»** выберите **«нет»** и нажмите **«Сохранить настройку»**.

## HTML-отчёт с сервера

24. На этом же ПК выполните `bad -r`.
25. Откройте в браузере файл. Путь напечатан в колонке **«Отчёт»**.

Команду выполняет служба `badagent`. Если сервер отдал HTML, в файле он. Если нет, файл собирается на ПК. Снимок в базу эта команда не пишет.

## Разбор минидампа

26. Откройте в панели карточку этого устройства.
27. В левом списке разделов нажмите **«Минидампы BSOD»**.
28. Под файлом с расширением `.dmp`, имя которого не `Memory.dmp`, нажмите **«Разобрать»**.
29. На ПК выполните `bad push`.
30. Обновите карточку устройства в браузере.
31. В блоке того же файла прочитайте поле **«Причина»**.

Сервер читает заголовок дампа и не хранит тело файла.

## Обновление уже установленного агента

Эти шаги — для ПК, где агент уже стоит. Обновления включены, цель — последняя версия в каталоге, у файла в каталоге есть SHA256.

32. Откройте **Параметры → Обновления агента**.
33. В блоке **«Загрузить установщик вручную»** выберите файл `bad-agent-3.1.3.msi`.
34. Нажмите **«Добавить в каталог»**.
35. В каталоге версий проверьте, что у `3.1.3` в колонке **SHA256** есть значение.
36. На карточке ПК откройте **«Параметры агента»** и проверьте строку обновлений: **вкл**, цель **latest**.
37. Дождитесь, пока в поле **«Версия агента»** на этой карточке станет `3.1.3`.

Кнопка из шага 34 кладёт файл в каталог сервера `/var/lib/bad/agent-updates/3.1.3/bad-agent-3.1.3.msi` и записывает SHA256. Уже установленный агент забирает эту версию сам, когда обновления включены и цель — latest.

Установщик не стирает файл настроек и не стирает ключ этого ПК. Если старая подпись не подходит к снимку, агент удаляет её и отправляет снимок ещё раз.

## Проверка связи

38. На ПК выполните `bad info`.
39. Прочитайте последнюю строку: поле **«Связь»**, значение **«есть»**, статус **ok**. Если сервер не ответил, значение **«нет»** и статус **ошибка**.

Команды `bad info`, `bad push`, `bad doctor`, `bad update`, `bad config` и `bad -r` выполняет служба `badagent`. Команды `bad ping` нет.

`bad doctor` сначала проверяет связь. Если ключ отклонён, в строках связь **есть**, ключ **отклонён**, заявка ждёт **«Разрешить»**. Обновление и сброс при этом не идут. Сброс настроек и стирание ключа подписи — только после принятого ключа и строки обновления.
